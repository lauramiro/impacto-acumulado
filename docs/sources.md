# Data sources

All values below were observed directly from live API responses and downloaded files captured on 2026-09-18 (fixtures for BOE/BOJA cover 2022-2024 documents; the reference layers and Groq model list reflect what was live on the capture date). Fixtures live under `pipeline/tests/fixtures/`.

## BOE

- Summary endpoint: `https://www.boe.es/datosabiertos/api/boe/sumario/{yyyyMMdd}` (path date, no query params). Example: `https://www.boe.es/datosabiertos/api/boe/sumario/20230918`.
- Headers: `Accept: application/json` works as documented in the brief; no other header was needed.
- Response envelope (confirmed from `pipeline/tests/fixtures/boe_sumario_20230918.json`, 351611 bytes):
  ```
  { "status": {"code": "200", "text": "ok"},
    "data": {"sumario": {"metadatos": {...},
      "diario": [ {"numero": "223", "sumario_diario": {...},
        "seccion": [ {"codigo": "3", "nombre": "III. Otras disposiciones",
          "departamento": [ {"codigo": 9575, "nombre": "MINISTERIO PARA LA TRANSICIÓN ECOLÓGICA Y EL RETO DEMOGRÁFICO",
            "epigrafe": [ {"nombre": "Impacto ambiental",
              "item": [ {"identificador": "BOE-A-2023-19635", "control": "2023/19437", "titulo": "...", "url_pdf": {...}, "url_html": "...", "url_xml": "..."} ] } ] } ] } ] } ] } } }
  ```
- JSON keys (for the item with `identificador` = `BOE-A-2023-19635`):
  - section code = `seccion.codigo` (e.g. `"3"`), section name = `seccion.nombre` (`"III. Otras disposiciones"`)
  - department name = `departamento.nombre` (`"MINISTERIO PARA LA TRANSICIÓN ECOLÓGICA Y EL RETO DEMOGRÁFICO"`, all caps in this JSON; note the XML document below gives the same department in title case)
  - epigrafe name = `epigrafe.nombre` (`"Impacto ambiental"`) - this is the most direct category filter for environmental-impact resolutions
  - item id = `item.identificador`, title = `item.titulo`, xml url = `item.url_xml` (`https://www.boe.es/diario_boe/xml.php?id=BOE-A-2023-19635`)
- Document XML (`GET https://www.boe.es/diario_boe/xml.php?id=<identificador>`, no headers needed): root element `<documento>`.
  - identifier element: `<metadatos><identificador>`
  - title element: `<metadatos><titulo>`
  - publication date element: `<metadatos><fecha_publicacion>` (format `YYYYMMDD`); there is also `<fecha_disposicion>` (signature date of the resolution, same format)
  - department element: `<metadatos><departamento codigo="9575">Ministerio para la Transición Ecológica y el Reto Demográfico</departamento>` (title case here vs. all-caps in the summary JSON)
  - body text element: top-level `<texto>` (direct child of `<documento>`, after `<analisis>`) containing `<p class="...">` paragraphs. Caution: a second, unrelated `<texto>` element also appears nested inside `<analisis><referencias><posteriores><posterior>` (short annotation text about a later correcting BOE entry) - a parser must select the top-level `<documento>/<texto>`, not the first `<texto>` found in document order in some libraries' traversal, since XPath `//texto` would match both.
- Selection rules: filter summary items where `epigrafe.nombre` == `"Impacto ambiental"` and `departamento.nombre` matches the Ministry for the environment (name observed: `"MINISTERIO PARA LA TRANSICIÓN ECOLÓGICA Y EL RETO DEMOGRÁFICO"` / `"Ministerio para la Transición Ecológica y el Reto Demográfico"` - this name is stable across the 2022-2025 fixtures found, unlike BOJA's department name below). Within the document body, the verdict is stated near the end as `"formula declaración de impacto ambiental [desfavorable] a la realización del proyecto/de la línea ..."` - presence of the word `"desfavorable"` immediately after `"impacto ambiental"` in that operative sentence marks an unfavorable verdict; its absence there marks favorable. Some resolutions cover multiple named installations with different verdicts per installation in the same document (see BOE-A-2023-2580 below) - a parser must not assume one verdict per document.
- Sample ids:
  - `BOE-A-2023-19635` (Plantas fotovoltaicas Ronda I, Ronda II y Ronda III, Cádiz/Málaga). The document's title names the plants and their evacuation infrastructure, but the only operative verdict sentence in the body is scoped to the evacuation line alone: `"formula declaración de impacto ambiental desfavorable a la realización de la línea de evacuación aéreo-subterránea 'L/220 kV Ronda - Pinar del Rey'"`. No separate favorable/unfavorable sentence for the plants themselves appears in this document (the text references a comparable project, PFV Sancho, as already having "DIA favorable" elsewhere, expediente PFot 479, but that is not this document's verdict). Treat this fixture as: line = unfavorable, plants = not adjudicated in this document.
  - `BOE-A-2023-2907` (favorable) - "Parque eólico Filabres, 153 MW, parque eólico Peregiles, 93 MW, y del parque solar fotovoltaico La Rambla, 100 MWp, ... en Tabernas, Tahal, Senés, Lucainena de las Torres, Níjar y Sorbas (Almería)". Operative sentence: `"formula declaración de impacto ambiental a la realización del proyecto ..."` with no `"desfavorable"` qualifier, followed by imposed conditions - a favorable DIA.
  - `BOE-A-2023-2580` (unfavorable) - "Plantas Solares Fotovoltaicas y sus infraestructuras de evacuación en el Nudo Jordana, en las provincias de Cádiz y Málaga". Operative sentence: `"formula declaración de impacto ambiental desfavorable a la realización del proyecto ... "Plantas Solares Fotovoltaicas y sus infraestructuras de evacuación en el Nudo Jordana ..." debido a que ... no puede descartarse que se produzcan impactos negativos significativos ..."`. Note this document names several individually-titled plants (Áncora Solar, Winche Solar, Nuza Solar I/II, Amura Solar, Trofeo Solar/Trofeo Solar II, etc.) with mixed per-plant findings in the body text even though the final operative declaration for the project as a whole is unfavorable - a good stress-test fixture for a parser that must not just keyword-match "favorable" without locating the operative sentence.

## BOJA

- OpenAPI description: `GET https://datos.juntadeandalucia.es/api/v0/boja/openapi.json` (saved to `tmp/boja_openapi.json`, gitignored - not a fixture). `info` block: `{"title": "pd-boja-ws-consultas", "description": "BOJA", "version": "0.0.1"}` - no `servers` entry; the base URL is inferred from the paths that work: `https://datos.juntadeandalucia.es/api/v0/boja/`.
- Search endpoint: `GET https://datos.juntadeandalucia.es/api/v0/boja/get/search_pagination`. Parameters, exactly as declared in the OpenAPI schema (the brief's assumed parameter names for the text query were wrong - corrected below):
  - `order_by` (required, string enum `_Enum_fields_3`: `-, id, title, number, ..., date, ..., publicUrl` etc.) - use `date` to sort by date.
  - `mode` (required, string enum `_Enum_Mode`: `DESC` / `ASC`, **uppercase** - the brief's example used lowercase `desc`, which the API rejects).
  - `size` (integer, default 0) - page size.
  - `page` (integer, default 0).
  - `general` (string, default `"-"`) - **this is the free-text query field**, not `general_search_like` as the brief assumed.
  - `general_search_like` (boolean, default false) - toggles LIKE-style matching for `general`; a plain multi-word `general` value already does a working token search without needing this flag set.
  - `summaryNoHtml` (string, default `"-"`) - an additional filter field, unused in our working query.
  - `date_from`, `date_to` (string, format `yyyy-MM-dd`, e.g. `2020-06-30` - the brief's assumed format was correct).
  - `campos` (array of `_Enum_fields_2`; repeat as `campos=a&campos=b&...` for multiple values - default `[id, organisation, summary, number, date, titleSec]` if omitted).
- Working example URL (produced `pipeline/tests/fixtures/boja_search_sample.json`, 20 results, all of them renewable-energy authorizations, out of `total_hits`: 792 matching the date window):
  ```
  https://datos.juntadeandalucia.es/api/v0/boja/get/search_pagination?order_by=date&mode=DESC&size=20&page=1&general=autorizacion+ambiental+unificada+fotovoltaica&date_from=2023-01-01&date_to=2024-12-31&campos=id&campos=organisation&campos=summary&campos=number&campos=date&campos=titleSec&campos=body&campos=bodyNoHtml&campos=publicUrl
  ```
- Response envelope: `{"hits": <int, records in this page>, "total_hits": <int, total matches>, "results": [ {...one object per record...} ]}`.
- Record fields observed in `boja_search_sample.json`: `id`, `number`, `date` (format `dd/MM/yyyy`, e.g. `"30/03/2023"` - note this differs from the `yyyy-MM-dd` input format for `date_from`/`date_to`), `titleSec` (e.g. `"3. Otras disposiciones"`, `"5. Anuncios"`), `organisation`, `summary` (HTML), `body` (HTML), `bodyNoHtml` (plain text). Requesting `campos=publicUrl` did not add a top-level `publicUrl` field - the public PDF URL instead comes back nested as `pdf: [{"publicUrl": "https://juntadeandalucia.es/eboja/...pdf", "pathPdf": ..., "id_file": ..., "hashPdf": ..., "signatureFile": ...}]` (a one-element array in every record we saw).
- Organisation name encoding note: some organisation strings contain U+00A0 (non-breaking space) between words, e.g. `"Consejería de Sostenibilidad, Medio Ambiente y\xa0Economía\xa0Azul"` - exact-string filters must normalize whitespace (e.g. collapse `\xa0` to a regular space) before comparing.
- By-id endpoint: `GET https://datos.juntadeandalucia.es/api/v0/boja/{bid}`, e.g. `https://datos.juntadeandalucia.es/api/v0/boja/disposition.2023.61.99` (id taken from a search result). Response has the same `{hits, total_hits, results}` envelope plus a `schema.fields` array documenting every possible field (33 fields total, including `pdf.publicUrl` etc. as dotted names). **The by-id response includes the full text**: `body` and `bodyNoHtml` contain the complete resolution text (in our sample, an "AAU" - autorización ambiental unificada - notice with the full "HA RESUELTO ... ANEXO ... Expediente / Promotor / Término municipal / Actuación" block), not just metadata.

### BOJA selection

- Title/summary phrases identifying relevant documents: `"autorización ambiental unificada"`, `"informe de impacto ambiental"` (also seen as `"informe vinculante sobre la autorización ambiental unificada"`), and `"información pública"` combined with a renewables word (`fotovoltaica`, `fotovoltaico`, `eólica`, `eólico`, `parque eólico`, `planta solar`).
- Organisation names publishing these authorizations, confirmed present in the 20-result sample (`boja_search_sample.json`), both from the current legislature:
  - `"Consejería de Sostenibilidad, Medio Ambiente y Economía Azul"` - the environment authority; publishes the AAU informe vinculante / DIA notices (titleSec `"5. Anuncios"` or `"3. Otras disposiciones"`).
  - `"Consejería de Economía, Hacienda y Fondos Europeos"` - the industry/energy authority; publishes grid-connection (AAP) resolutions, including denials (`"se deniega la Autorización Administrativa..."`).
  - The full historical organisation list (`GET /api/v0/boja/option-values/organisation`, 1000 values returned, not confirmed exhaustive) confirms the environment department's name has changed repeatedly across legislatures, e.g.: `"Consejería de Medio Ambiente"`, `"Consejería de Medio Ambiente y Ordenación del Territorio"`, `"Consejería de Agricultura, Pesca y Medio Ambiente"`, `"Consejería de Sostenibilidad y Medio Ambiente"`. The industry/energy side has similarly changed: `"Consejería de Industria, Energía y Minas"`, `"Consejería de Política Industrial y Energía"`, `"Consejería de Economía, Industria y Energía"`, among others. A selection filter should match on a substring/keyword basis (`"Medio Ambiente"` or `"Sostenibilidad"` for the environment side; `"Industria"` or `"Energía"` for the grid/AAP side) rather than an exact current name, given this turnover.

## LLM

- Provider: Groq. Live model list: `GET https://api.groq.com/openai/v1/models` with `Authorization: Bearer $IMPACTO_LLM_KEY`.
- **Deviation from the brief**: `llama-3.3-70b-versatile` is **not** in the current model list, and in fact no Llama chat/completion model is available at all. The full list of 13 models returned (2026-09-18): `allam-2-7b`, `canopylabs/orpheus-arabic-saudi`, `canopylabs/orpheus-v1-english`, `groq/compound`, `groq/compound-mini`, `meta-llama/llama-prompt-guard-2-22m`, `meta-llama/llama-prompt-guard-2-86m`, `openai/gpt-oss-120b`, `openai/gpt-oss-20b`, `openai/gpt-oss-safeguard-20b`, `qwen/qwen3.8-27b`, `whisper-large-v3`, `whisper-large-v3-turbo`. The two `llama-prompt-guard-2-*` entries are small (22M/86M parameter) safety classifiers, not usable as a general chat/completion model, so the brief's fallback ("choose the largest available Llama model") does not apply.
- **Model chosen**: `openai/gpt-oss-120b` - the largest available general-purpose chat model (120B params, 131072-token context window, supports `tools`, `json_mode`, `structured_outputs`, `reasoning`). Set `IMPACTO_LLM_MODEL=openai/gpt-oss-120b`.
- Free-tier limits for `openai/gpt-oss-120b`, confirmed two ways: (a) live response headers from a real `POST /openai/v1/chat/completions` call (`x-ratelimit-limit-requests: 1000`, `x-ratelimit-limit-tokens: 8000`), and (b) cross-checked against the published table at `console.groq.com/docs/rate-limits`, where `x-ratelimit-limit-requests` is documented as requests-per-day: **RPM 30, RPD 1000, TPM 8000, TPD 200000**.
- Operational note: an unauthenticated-looking request to `api.groq.com` without a normal `User-Agent` header gets blocked by Cloudflare with `HTTP 403` and body `error code: 1010` (bot-signature block) - Python's default `urllib` User-Agent triggers this. The pipeline's HTTP client must send a realistic `User-Agent` (a plain `curl/8.0` string was sufficient) for both the `/models` and `/chat/completions` endpoints.

Both failures were recorded as `status = 'failed'` rows with `attempts = 1` (2 retries left before the 3-attempt cap) rather than crashing the stage, and `GroqProvider`'s own 6-attempt exponential backoff (10s/20s/40s/80s/160s) ran to exhaustion correctly before the underlying `RateLimitError` was re-raised and caught by `run_extract` - the backoff logic works as designed, it simply cannot out-wait a multi-minute daily-quota reset.

### Note on tooling for this task

`ogrinfo` was not installed, and the ruling's fallback command (`uv run --with geopandas --with pyogrio ...`) failed on this machine with `ImportError: DLL load failed while importing _cyutility / nattype: Una directiva de Control de aplicaciones bloqueó este archivo` (a Windows Application Control policy blocking pandas' compiled Cython extensions) - this reproduced identically under both the system Python (3.14) and a uv-provisioned Python 3.12, so it is a machine policy, not a version mismatch. Vector inspection was done instead with the pure-Python `pyshp` package (no compiled extensions), and raster inspection with `tifffile` + `imagecodecs`. Both avoided the blocked DLL path and produced results cross-checked against each dataset's own metadata (the `.prj` WKT for the shapefile; the `leeme_valores ISA.pdf` readme and embedded GeoTIFF tags for the raster).
